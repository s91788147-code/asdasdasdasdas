# Покерный LLM-аналитик (прототип)

LLM для разбора раздач No-Limit Texas Hold'em: сила руки, дро и ауты («% доезда»), эквити против диапазона, шансы банка, решения колл/фолд/рейз, анализ блефа.

## Главная идея: LLM рассуждает, код считает

Если просто спросить языковую модель «какое у меня эквити», она часто ошибается: комбинаторика и вероятности — слабое место LLM. Оптимальную стратегию модель тоже знает лишь приблизительно — её находит солвер (алгоритмы семейства CFR). Это подтверждают исследования:

- [PokerBench](https://arxiv.org/abs/2501.08328) (AAAI 2025). Лучшая модель без дообучения (GPT-4) выбирала оптимальное действие примерно в 54% спотов, дообученная Llama-3-8B — примерно в 78%. При этом в игре против GPT-4 авторы увидели пределы простого дообучения.
- [ToolPoker](https://arxiv.org/abs/2602.00528) (ICLR 2026). LLM вызывает солвер как инструмент.

Поэтому здесь гибрид:

```
вопрос: «AhKh на Qh7h2c, банк 100, ставка 50 — колл?»
        │
        ▼
LLM (Claude): понимает спот, строит диапазон оппонента,
решает, что посчитать, объясняет вывод
        │  вызовы инструментов (tool use, JSON)
        ▼
poker_engine: точная математика
  analyze_hand · calculate_equity · count_outs
  range_breakdown · pot_odds · bet_math
```

## Что в репозитории

| Путь | Что делает |
|---|---|
| `poker_engine/evaluator.py` | Сила руки из 5–7 карт; проверена на всех 2 598 960 пятикарточных руках |
| `poker_engine/ranges.py` | Диапазоны: `QQ+, AKs, A2s+, 99-66, JTs-54s, top15%, AKo:0.5` |
| `poker_engine/equity.py` | Эквити 2+ игроков (рука или диапазон): точный перебор или Монте-Карло |
| `poker_engine/analysis.py` | Класс руки (сет, топ-пара…), дро, ауты, «% доезда», состав диапазона, блокеры |
| `poker_engine/odds.py` | Шансы банка, EV колла, implied odds, MDF, безубыточность блефа, доля блефов, EV полублефа |
| `poker_agent/` | Агент на Claude API: системный промпт, 6 инструментов, цикл tool use |
| `scripts/make_sft_dataset.py` | Генератор обучающего датасета для дообучения open-source LLM |
| `scripts/build_preflop_ranking.py` | Пересчёт рейтинга 169 стартовых рук (для `topN%`) |
| `tests/` | Эталонные значения эквити и формул, протокол агента на поддельном клиенте |

## Быстрый старт

Нужен Python 3.10+.

```bash
pip install -r requirements.txt

# Движок работает без LLM и без ключа:
python -m poker_engine hand AhKh --board Qh7h2c                     # комбинация, дро, ауты, % доезда
python -m poker_engine equity AhKh "QQ+, AQs+, 77, 22" --board Qh7h2c
python -m poker_engine outs AhKh 7c7d --board Qh7h2c                # 8 аутов: 2h даёт сету фулл-хаус
python -m poker_engine range "QQ+, AQ, KQs, T9s" --board Qh7h2c --hero AhKh
python -m poker_engine odds --pot 150 --call 50 --equity 39
python -m poker_engine bet --pot 100 --bet 75 --fold-equity 40 --equity 30

# Агенту нужен ключ Anthropic API:
export ANTHROPIC_API_KEY=...
python -m poker_agent "6-max, 100bb. Открыл CO с AhKh, BB заколлировал. Флоп Qh7h2c, BB ставит 2/3 банка. Что делать?"
python -m poker_agent            # диалог с уточняющими вопросами
python -m poker_agent -v "..."   # показывать ответы инструментов

python -m pytest                 # тесты
```

По умолчанию используется модель `claude-opus-5` с adaptive thinking. Модель меняется через `--model` или переменную `POKER_AGENT_MODEL`, глубина рассуждений — через `--effort low|medium|high|xhigh|max`. Если классификаторы безопасности отклонят запрос, сервер повторит его на другой модели (`fallbacks: "default"`).

## Что считается и как

| Величина | Формула / метод |
|---|---|
| Эквити | доля банка к риверу: точный перебор раскладов, если он быстрый, иначе Монте-Карло с погрешностью |
| Ауты, «% доезда» | перебор всех невидимых карт; на следующей карте `ауты / невидимые`, с флопа к риверу `1 − C(невидимые − ауты, 2) / C(невидимые, 2)`, плюс правило «4 и 2» |
| Шансы банка | нужное эквити = `колл / (банк + колл)`, где банк уже включает ставку оппонента |
| EV колла | `эквити × (банк + колл) − колл` |
| Implied odds | сколько ещё нужно выиграть при попадании: `колл × (1 − эквити) / эквити − банк` |
| Безубыточный блеф | `ставка / (банк + ставка)` — как часто оппонент должен сбрасывать |
| MDF | `банк / (банк + ставка)` — минимальная частота защиты против ставки |
| Доля блефов на ривере | `ставка / (банк + 2 × ставка)` — при такой доле оппоненту всё равно, коллировать или нет |
| EV полублефа | `FE × банк + (1 − FE) × (эквити × итоговый банк − ставка)` |

## Как агент анализирует блеф

1. Строит диапазон оппонента по позиции и всей линии. Пример: ставка BB на флопе Qh7h2c — это сеты, две пары, топ-пары, флеш-дро и немного воздуха.
2. `range_breakdown` с рукой героя показывает, сколько комбинаций этой линии бьют героя (вэлью), а сколько — блефы и дро. Там же видно, какие комбинации блокирует рука героя.
3. `pot_odds` даёт эквити, нужное для колла, а `bet_math` — долю блефов, которая была бы сбалансированной при таком размере ставки.
4. Из сравнения этих чисел следует решение. Если реальный оппонент блефует реже баланса, колл хуже, и агент это оговаривает.

## Как дойти до «своей LLM»

Обучать модель с нуля не нужно. Реалистичный путь:

1. **Промпт и инструменты (этот репозиторий).** Самый быстрый способ получить точные цифры и внятные объяснения. Улучшается правкой промпта и инструментов.
2. **Проверочный набор (eval).** 50–200 спотов с эталонными ответами (из солвера или от сильного игрока). Без него не понять, стала ли система лучше после изменений.
3. **Стратегия из солвера.** Инструмент `solve_spot` поверх солвера:
   - [TexasSolver](https://github.com/bupticybee/TexasSolver) — C++, AGPL;
   - [postflop-solver](https://github.com/b-inary/postflop-solver) — Rust, разработка приостановлена;
   - [noambrown/poker_solver](https://github.com/noambrown/poker_solver) — только ривер, MIT.

   Тогда LLM объясняет стратегию солвера, а не придумывает её.
4. **Данные.**
   - [PokerBench](https://huggingface.co/datasets/RZ412/PokerBench): около 560 тыс. спотов 6-max NLHE с решениями солвера, формат «описание → действие».
   - [PHH dataset](https://github.com/uoftcprg/phh-dataset): 21 млн онлайн-раздач и 10 000 раздач Pluribus.
   - Ваши истории рук: [pokerkit](https://github.com/uoftcprg/pokerkit) читает форматы PokerStars и других румов.
   - Синтетика из `scripts/make_sft_dataset.py`: цифры в ней точные, их считает движок.
5. **Дообучение open-source модели.** Нужно, если модель должна работать локально, дёшево или без отправки данных наружу. LoRA/QLoRA через [TRL](https://github.com/huggingface/trl) (`SFTTrainer`) или [Unsloth](https://github.com/unslothai/unsloth) на модели 4–9B (Qwen3/Qwen3.5, Gemma, Llama 3.1 8B) — это умещается на одной видеокарте. Формат `messages` из генератора подходит напрямую. Математику и после дообучения лучше оставить инструментам (function calling).
6. **RL поверх дообучения.** Пример — [SpinGPT](https://arxiv.org/abs/2509.22387): сначала обучение на решениях экспертов, затем RL на раздачах солвера. Силу бота можно проверять против [Slumbot](https://slumbot.com) через его открытый API.

## Ограничения

- Это не солвер: диапазоны — допущения модели, эквити на флопе и терне не учитывает будущие ставки (implied и reverse implied odds).
- `topN%` — рейтинг по эквити против случайной руки. Для реальных диапазонов открытия лучше явные чарты.
- Движок написан на чистом Python: около 370 тыс. оценок руки в секунду, Монте-Карло на 30 000 раздач считается за доли секунды. Для массовой генерации данных можно взять [eval7](https://github.com/julianandrews/pyeval7) или [phevaluator](https://github.com/HenryRLee/PokerHandEvaluator).
- Проект — для разбора раздач и обучения. Подсказки во время игры (RTA) запрещены правилами покер-румов: за них блокируют аккаунт и конфискуют баланс.
